# Square / Clover 收银系统连接

本说明对应餐厅外卖1.0.2。Square/Clover仅开放测试环境，正式营业连接尚未开放。真实品牌账号与设备尚未验收，不能把本地验证理解成已具备营业接入资格。

## 餐馆老板如何操作

1. 后台「餐厅外卖 → 收银系统」，选择 Square 或 Clover，登录自己的品牌账号并允许连接。
2. 选择正确门店，核对门店名称、地址；当前候选只支持美元门店。
3. 给网站每道菜选择对应的收银菜品。午餐、晚餐和儿童餐可各自对应。不会覆盖收银菜单、修改网站售价或导入真实商户资料到其他网站。
4. 选择谁负责厨房出单：「网站打印助手」或「收银系统」。本版不接管营业打印，网站原有打印队列始终保留。选择网站打印助手时，POS只记账，不能承诺同时出现在接单屏；商户已有其他自动打印应用时，须现场核对避免重复。
5. Clover 还需选择店家事先开通的「网站已付款」外部收款方式、对应税项及自取/配送订单类型。这些选项从商户账号读取，不要求输入内部编号。
6. 获得现场允许后发送零金额测试单。测试单明确标识「TEST ONLY / 不出餐 / SOLO PRUEBA」。等待约一分钟，点击「刷新连接及传单进度」，在收银机核对文字、接单位置和出单方式，再勾选收到确认。接口确认不代表打印成功。
7. 点击开启以后新订单自动接入。开启前必须确认这是仅使用测试资料和测试付款的测试站。只处理开启后新建、经网站原收款系统确认全额付款且未退款/取消/交餐的测试订单，不自动补发历史订单。

菜品成交价包含已选付费加料；规格、加料名称和每道菜备注一起传送。Square即时自取/送餐的预计分钟可在对应页面填写；顾客指定的预约时间优先。数量、税费、配送费、自取/送餐方式与预约时间来自网站原订单，不由浏览器金额决定。当前通过备注携带额外选项，没有创建第二套POS加料价格表。

「接口已确认收到」只表示订单、金额和外部付款登记已回读核实；厨房是否出纸须现场确认。网站已付款，POS只做外部收款登记，不再向顾客扣款。订单传给POS以后如取消、退款或更改，店家必须人工通知厨房并核对POS；这里不会自动取消POS订单或自动退款。

传送中断、金额不符或结果不确定时，后台会提示核对收银机，并保留已取得的收银订单号；不会盲目再发一次。暂停后可人工接单。断开只清除本网站该连接凭据；彻底撤销授权须到品牌账号移除此应用。

## 管理员只需提前开通

尚无品牌应用时页面显示「等待管理员开通」，不会假装已连接。管理员展开「首次开通」，选择测试环境并填写品牌应用编号。普通餐馆老板不需要填写支付密钥或品牌密码。

- Square：创建 OAuth 应用并支持 PKCE；登记页面显示的回到本网站的网址。权限：商户读取、菜单读取、订单读取/写入、付款读取/写入；付款写入用于外部已收款登记。
- Clover：当前候选采用低信任应用的 PKCE 授权流程，不支持把高信任应用秘密混入这一流程。需申请商户资料、库存读取以及订单和外部付款所需权限；按厂商要求登记回到本网站的网址，并确认应用分发/商户安装资格。
- 网址由 CMS 配置的 `site.url` 生成，不采用请求头中的任意主机名。本版禁止正式POS环境；测试站公开网址必须HTTPS，本机可使用HTTP。真实授权通常还需品牌认可的公开回调网址。
- 应用设置和商户凭据使用 CMS 原生 `PluginSecretStore` 加密；CMS必须已配置有效加密主密钥。不要把令牌写到店面展示资料、主题文件或聊天。
- 插件通过 `PluginContext::registerScheduledTask` 注册每60秒运行的 `restaurant.pos_sync`。网站现有原生计划任务执行器需要正常运行；后台在近期没有执行记录时禁止开启自动接单。无需为每个餐馆编写独立任务代码。
- 如需管理员诊断，可使用原生安装环境中的 `php content/plugins/official.restaurant/bin/reconcile-pos-orders.php --once`。它检查安装状态、维护/恢复状态、插件信任及启用状态；不适用于未通过原生安装的源码副本。未配置品牌应用时不会连接品牌服务。

当前有意限制：每站一个自动接入目标；美元；菜单读取限5页（Clover每页100条），超过时停止并提示管理员处理；单单最多250份。税费、规格、配送/预约及打印设置必须用真实测试商户核对。没有为 Toast、Lightspeed、Aloha 或 MICROS 提供假连接。
