# 菜单识别与顾客特别要求

## 菜单录入

后台 → 餐厅外卖 → 识别菜单。上传 PDF、JPG/PNG/WebP、UTF-8 TXT/CSV，或粘贴文字；原来的“菜单 → 新增/编辑”不变。

1. 识别只生成当前登录会话中的待审核草稿，1 小时有效，不创建菜品。
2. 对照原件修改菜名、分类、午餐/晚餐/儿童份量、价格、币种与配料说明；取消勾选即可排除误识别行。
3. 勾选已核对，再确认导入。另勾选“导入后设为可售”才开启销售，否则停用、稍后人工开启。
4. 同名、同分类、同分组已有菜品跳过，不覆盖人工记录；更新已有菜品仍使用编辑页。
5. 空白价格或分类必须补齐。识别可能漏菜、混淆标题/说明、拆错组合价，不保证完整，禁止不核对直接启售。午餐份量不设置限时。

CSV 示例（价格仅用于测试）：

```csv
name,category,menu_section,price,description
LOCAL TEST Chicken,Wok,lunch,9.95,"Chicken, peppers"
LOCAL TEST Chicken,Wok,dinner,14.95,Dinner portion
LOCAL TEST Rice,Kids,kids,6.95,Small portion
```

支持此前 `name_en,price_usd` 待审核 CSV。没有价格的行保留空白，不能凭空补价。原文只用于会话核对；菜单记录保留来源摘要，不保存上传原件。

## 识别组件与隐私

- 文字 PDF：Poppler `pdftotext`；扫描 PDF：`pdftoppm` + Tesseract；图片：Tesseract。可使用服务器环境变量 `RESTAURANT_PDFTOTEXT`、`RESTAURANT_PDFTOPPM`、`RESTAURANT_TESSERACT` 指定受信任的绝对程序路径，后台表单不接受可执行路径或远程文件 URL。
- 对应 OCR 语言包：`eng`、`chi_sim`、`spa`。程序不可用、PHP 禁止进程或缺少语言包时，使用 TXT/CSV/粘贴文字，不需要逐道输入。
- 只有明确勾选同意，才通过现有 CMS 站点 AI 整理文字；可能产生现有服务费用。复用站点 AI 设置，不新增密钥配置，不发送原始照片/PDF。站点 AI 未配置时不能假称完成 AI 识别。
- 文件 ≤10 MB，图片 ≤2000 万像素，PDF 最多前 6 页；文字 ≤60 KB、草稿 ≤200 行；每个子进程 ≤30 秒，整份文件处理 ≤90 秒。超限失败，不部分导入。
- PHP 建议 `upload_max_filesize=10M`、`post_max_size=12M`、`max_input_vars=2000`，并匹配 Web 服务器请求体/超时限制。界面显示实际 PHP 限制；表单被截断时拒绝导入，保留草稿。
- 混合文字/扫描、多栏、共享价格、酒水和跨行菜名必须人工检查；需要排除非在线可售商品。AI 也不替代核对。

## 顾客额外要求

每道菜卡片下方有独立“备注”，顾客自己填写不要鸡肉、不要米饭、酱汁另放等要求；打开这道菜的点餐窗口后，备注会自动带入，也可以继续修改。不再展示“不要什么”的预设勾选框。不同菜品备注不串行，筛选/语言切换不会丢失当前备注；成功加入餐车后清空输入，内容保留在餐车/票据。

只承诺厨房能接受的项目；自由说明不是厨房已经同意的承诺，不能自动减价或免费增加收费加料，过敏需求须直接联系门店。

### 收费加料

后台菜单编辑页只有一个“加”入口：点“加” → 从下拉框选择米饭/鸡肉/牛肉/其他 → 输入每份加多少钱 → 保存菜品。可添加多个加料行、移除某行；米饭/鸡肉/牛肉自动提供中英西名称，不用再输入竖线格式或 JSON。

“其他”需填写名称，英文/西语可在可选设置中填写；未提供翻译时保留原名称，不伪称已翻译。价格使用菜品币种，由后台管理员设置。例如加米饭 1.50、加鸡肉 3.00、加牛肉 4.00 仅为本地测试示例，不是门店确认价。

顾客窗口也只有一个“加”分区：选择要加的东西（显示后台加价）→ 点“加”；已选加料可移除、可继续加其他项目，不能重复加入同一项目或自己输入价格。原尺寸/规格等 Modifier 保持原界面。

顾客可选择多项，餐车显示各项加价、该行合计与总价。每个选择表示每份菜的对应加料；点两份时 `(菜价 + 所选加料加价合计) × 2`，不是整单只收一次加料费。若要提供“两份额外米饭”，可单独定义该选项并设置对应价格。

复用现有 Modifier 服务器计价，不采信客户端传来的价格。后台修改加料价后，旧餐车不能以旧价继续结算，须重新选择。编辑器只管理 `paid_addons`；原其他 Modifier 和历史 `special_requests` 数据不删除，老餐车/订单仍保留原有内容。历史“不要什么”的预设仅在新界面隐藏，新顾客通过备注填写。自由备注“多加肉”不能自动获得免费加料，应选择门店配置的收费项目。

所有可售菜品均可打开数量/特别说明弹窗，即使没有预设规格。最多 500 字的自由备注和已选选项保存在餐车，沿用现有订单转厨房票流程；购物车可核对，厨房票的待打印内容会显示选项与备注。本功能不证明实体打印机已连接，也不修复其他支付事件漏票问题。
