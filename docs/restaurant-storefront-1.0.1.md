# 餐厅外卖与戴影餐厅外卖主题 1.0.1

本次由 Owner 明确授权将现有餐厅插件、主题源码加入公开仓库；它们仍是独立市场扩展，不是新增 Core 模块。本次不修改、升级或发布 Core，不更新其他插件或生产网站。

## 首选语言

在「餐厅外卖 → 店面与营业设置 → 首选语言」选择 English、中文或 Español。未配置时，新访客默认英文；已在浏览器选择语言的顾客继续使用原选择。语言设置不清空购物车，也不追溯修改订单。

公开 storefront API 新增 `default_locale`；没有 locale 查询参数时，storefront 与 menu API 使用门店首选语言。有明确 locale 的请求保留顾客选择。未识别的浏览器语言存储值会忽略；插件缺失时主题仍安全降级。

## 安装与费用边界

- 插件 `official.restaurant`、主题 `daiying-restaurant-storefront`，本次版本均为 1.0.1；显示名称分别为「餐厅外卖」「戴影餐厅外卖主题」。
- 运行依赖 Core ≥1.2.83、兼容的官方 Commerce ≥1.0.8；结账会核对公开 `orderPaymentState` 等能力。仓库自带 Commerce 不等于市场正式版本，必须按实际能力验收，不能移除检查强行通过。
- 官方插件需走受支持的应用市场授权、签名与信任验证流程，不能当作普通本地插件 ZIP 绕过保留身份限制。
- 保持既定销售规则：插件 USD 2,000／终身使用／每站；主题免费。公开源码不代表生产授权码、支付通道或服务自动免费，不修改现有授权/订单身份。
- 使用该功能需同时更新餐厅插件和配套主题；旧主题不会自动识别新首选语言字段。

## 验证方式

`tests/restaurant_preferred_language.php` 和 `.mjs` 覆盖后台保存、三语默认、浏览器手动选择优先、无效值和旧插件降级。JS 使用隔离 DOM/网络单元夹具，不是实体浏览器或手机验收。

相关集成测试应对安装了正式 Commerce 依赖和本次精确包的隔离宿主运行，通过 `RESTAURANT_TEST_ROOT` 指定根目录；不要直接把 bundled Commerce 的能力缺失误记为语言测试通过。签名及原生升级门禁只在授权更新服务器隔离目录执行，不能在工作站生成或读取签名私钥。
