# 首次安装失败的人工处理

适用于首次安装、尚未正式运行的网站。已正式运行的网站必须使用官方备份、升级及回滚流程，不能删除数据库来解决升级问题。

1. 保留错误提示和服务器日志，先修复数据库连接、扩展、目录权限或其他实际失败原因。安装失败不是安装成功。
2. 如果管理员已经提交但完成锁写入失败，公开安装入口将阻断。保留数据库和生成的配置，不重建管理员、不覆盖密码、不删除管理员。由拥有服务器权限的站点负责人备份后检查 `config/app.php` 的数据库与站点身份、`storage/installed.lock`、`storage/installing.lock` 和运行目录权限。安装锁必须与数据库及站点身份一致；不要在未核对安装完整性的情况下自行创建完成锁。
3. 若决定放弃这次新安装，先确认数据库名称、所属网站、使用账号、是否专用，以及是否有业务数据或其他网站共用表。对任何需要保留的数据先备份。存在疑问时停止清理。
4. 只有负责人明确确认数据可丢弃后，才人工清理这次失败安装的专用资源、重新创建空数据库。同时核对配置和安装状态文件；只清数据库通常不够。不得自动删除配置、安装锁或其他网站资源，也不得照搬未核实的删除命令。
5. 用空的专用数据库重新运行安装向导。确认完整迁移、管理员登录、配置和完成锁均正常。已完成安装不允许重复运行。

MySQL 的 DDL 不具备 SQLite 式的全链事务回滚保证。部分表、失败索引或安装中断不能默认当作可直接重试；需要负责人核查或按上述条件人工重新安装。产品不提供自动数据库清理或自动恢复状态机。
