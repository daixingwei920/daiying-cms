## 知识进入客服的闭环

正式发布事件 → 持久收件箱/队列 → 固定Git发布版本和知识修订 → USER-FACING准入 → 其他文件消费者 → 客服数据库事务 → 活动回执 → 原生Retriever/Responder → HTTP回答与来源回执。

仅接收真实已发布版本，拒绝Draft/prerelease、候选、错版本、伪造证据和内部资料。每来源最多256条，超限拒收；不静默截断。来源正文、活动回执和逐行哈希一致才可检索；Core事实必须匹配实际运行Core版本。回执保存版本、来源commit、知识commit、快照摘要与行哈希，回答携带对应来源。

首次成功激活后，站点进入严格托管模式。有匹配时只使用最高可用P0/P1/P2级别；旧FAQ快捷返回、旧chunks和旧500条列表不能绕过准入。旧数据保留但不自动晋级。未知、撤回或校验失败返回资料不足，不通过旧FAQ复活答案。未激活站点保持旧行为。插件没有新增SQL迁移；沿用站点隔离和Core AiService/AiGateway。

导入行、撤回行、回执和托管标记使用同一事务。写入失败保留旧活动批次；重试成功后再切换。其他文件消费者先行，避免其失败时客服提前使用新批次；跨文件/数据库仍无全局事务，状态报告保留部分应用与重试信息，不谎报全部完成。

## 蜘蛛观测与统计口径

主采集日志继续使用非阻塞锁、2,000条/512 KiB上限及命名公开路由。新观测仅记录开启采集后、已识别UA对受支持公开路由的GET/HEAD结果，分类为：写入成功、锁忙、条数上限、字节上限、无效日志、I/O失败、不安全符号链接、计数上限。不开启采集、私有路由、POST和未知UA不生成观测。

观测固定8片，每片最多8 KiB、最多30天、每原因每日最多10,000,000次；非阻塞且不递归记录自身失败。保留期复用原设置，原prune命令一并清理。管理读取不生成计数，不保存IP、原始UA、查询串或具体slug。新增页面沿用管理权限和private/no-store。

本机四进程400次尝试：主日志251次，观测锁忙149次；另一次采样脚本为246/400。受控锁忙0/400和串行400/400继续通过。这些只是各次隔离结果，历史109/400不是固定采样率。独立观测锁测试证明主日志新增5次时观测可以新增0次，因此所有观测为下界；不能算线上完整访问量或真实丢样率。

后台观测只随时间窗口变化，不随平台、蜘蛛、HTTP状态筛选变化；页面明确禁止与上方筛选结果相减或直接比较。“不可读取分片”是当前状态，不是丢失请求数。UA仍只是自称，未做真实来源核验，不代表收录或AI引用。
