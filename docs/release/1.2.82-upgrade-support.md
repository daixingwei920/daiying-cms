# 1.2.82 直接升级支持契约（Owner 已批准）

仅支持 1.2.81 → 1.2.82（当前验证目标为 1.2.82-rc1/testing）。
签名 update.json 与外部 metadata 的 source_versions 均为 min=max=1.2.81；min_upgrade_from、hard_min_version、migration_floor 均为1.2.81。构建及 parity 拒绝覆盖这一正式契约。此调整不改变旧发布包或49份历史迁移。

## 更新服务器发布前要求

本轮不操作生产分发配置。正式发布前，针对本次1.2.82包逐项验证：

- 导入最低及最高来源版本；不要只改产品全局版本字符串。
- current_version 缺失、无效或不在批准来源范围时，update_available=false、direct_upgrade_supported=false，响应不得提供本次包的 package_url 或下载准备入口。
- 1.2.81 通过版本、PHP、数据库、渠道、灰度等既有条件后才可领取。
- 包领取仍须由签名清单验证版本范围、完整性及签名；客户端下载按钮的判断不能代替服务端筛选。
- 直接下载公开文件不等于支持升级；不能声称匿名静态文件在任何条件下不可被人工取回。
- 对旧版本查询允许返回旧版仍支持的更新或明确不支持本次直升，不能因此删除历史版本。
- 正式canonical preflight、签名及发布授权完成前，testing候选不得标为stable/current。

若只返回 compatibility=false 但仍提供包地址，应视为本次分发验收未完成。服务器正式源码或获批隔离副本不可用时，记录BLOCKED，不用历史快照冒充现行实现。不绕过旧更新器、不设计过渡包、不修改客户数据。
